# 签名与打包流程（Windows / macOS）

> 适用范围：Renomio 0.1.x。脚本位于 `app/scripts/sign/`，全部**默认不签名**、缺证书时明确提示并退出，不会伪造“已签名 / 已公证”。

## 0. 本机现状（诚实说明）

| 项目 | 状态 |
| --- | --- |
| Windows 发布构建（NSIS） | 脚本已就绪；本机执行 `npm run tauri build` 的产物为**未签名**，SmartScreen 会提示未知发布者 |
| Windows 证书 | 本机**没有**代码签名证书（EV/OV 均无），因此未产生签名产物 |
| macOS 构建 / 签名 / 公证 | 脚本已就绪；本机为 Windows，**无法执行** macOS 构建与公证，未产生任何 macOS 产物 |
| Sidecar 签名链 | 当前版本没有 sidecar 二进制；脚本已按“先内层、后外层”实现，后续接入 FFmpeg 等可直接复用 |

## 1. 构建命令

```powershell
# 开发运行
npm run tauri dev

# Windows 发布包（NSIS，未签名）
powershell -File scripts/sign/build-windows.ps1

# Windows 发布包 + 签名（需证书，见下）
powershell -File scripts/sign/build-windows.ps1 -Sign
```

```bash
# macOS 发布包（.app + .dmg）
./scripts/sign/build-macos.sh

# macOS 签名 + 公证
APPLE_SIGNING_IDENTITY="Developer ID Application: xxx (TEAMID)" \
NOTARY_PROFILE=AC_NOTARY \
./scripts/sign/build-macos.sh --notarize
```

产物位置：

- Windows：`src-tauri/target/release/renomio.exe`、`src-tauri/target/release/bundle/nsis/*.exe`
- macOS：`src-tauri/target/release/bundle/macos/*.app`、`bundle/dmg/*.dmg`

## 2. Windows 代码签名

### 2.1 OV 证书（文件型）

1. 从 CA 获取 `.pfx`（含私钥）与密码。
2. 在构建机导入证书，或直接使用文件：

```powershell
$env:WINDOWS_CERT_PFX = 'D:\certs\renomio.pfx'
$env:WINDOWS_CERT_PASSWORD = '***'      # CI 用 secret 注入，不要提交到仓库
powershell -File scripts/sign/windows-sign.ps1 -Files <exe>,<installer>
```

3. 脚本调用 `signtool sign /fd sha256 /f ... /tr <timestamp> /td sha256`，随后 `signtool verify /pa /v` 校验。

### 2.2 EV 证书（硬件令牌 / HSM）

EV 私钥不可导出，签名通过证书存储或云签名服务完成：

```powershell
# 令牌已插好、驱动已装：读取证书指纹
Get-ChildItem Cert:\CurrentUser\My -CodeSigningCert | Format-Table Subject,Thumbprint
$env:WINDOWS_CERT_THUMBPRINT = 'A1B2...'
```

脚本执行 `signtool sign /sha1 <thumbprint>`。

云签名（Azure Trusted Signing 等）接入点：把 `windows-sign.ps1` 中 `signtool sign` 一行替换为对应 CLI / dlib 调用，保持“签名 → verify”两步即可。

### 2.3 无证书策略

- 开发 / 内测：允许未签名产物，文档与本回复中都明确标注。
- 发布：`build-windows.ps1 -Sign -RequireSign`，缺证书直接失败，避免把未签名包当正式包发出去。
- 时间戳服务：`WINDOWS_TIMESTAMP_URL` 可覆盖，默认 DigiCert。离线内网需换成内网 TSA，否则签名会因取不到时间戳失败。

### 2.4 需要签名的对象

1. 主程序 `Renomio.exe`
2. NSIS 安装包 `*-setup.exe`
3. 若后续增加 updater，`*.nsis.zip` 与 `.sig` 走 Tauri updater 签名（另一套 minisign 密钥，不是 Authenticode）

## 3. macOS 签名 + 公证

### 3.1 证书与身份

1. Apple Developer Program 账号创建 **Developer ID Application** 证书。
2. 安装到钥匙串后：

```bash
security find-identity -v -p codesigning
export APPLE_SIGNING_IDENTITY="Developer ID Application: Your Name (TEAMID)"
export APPLE_TEAM_ID="TEAMID"
```

### 3.2 签名链顺序（脚本已实现）

```
Contents/Frameworks/*.dylib / framework
        ↓
Contents/MacOS/<sidecar 可执行文件>     ← externalBin 放置位置
        ↓
Contents/MacOS/<主可执行文件>
        ↓
Renomio.app（外层 Bundle）
```

要点：

- 每个 Mach-O 都必须带 `--options runtime`（Hardened Runtime）和时间戳。
- `--entitlements src-tauri/entitlements.plist`：已包含 `allow-jit`（WKWebView 需要）与 `disable-library-validation`（sidecar / 插件）。
- **不要**对外层使用 `--deep` 跳过内层签名；脚本逐个签内层，最后签外层。
- 新增 sidecar 时无需改脚本：`Contents/MacOS` 与 `Contents/Resources` 下的可执行文件会被自动发现并先签。

### 3.3 公证（notarytool）

三种凭据任选其一（脚本自动识别）：

| 方式 | 环境变量 | 说明 |
| --- | --- | --- |
| API Key（推荐 CI） | `APPLE_API_KEY`、`APPLE_API_KEY_ID`、`APPLE_API_ISSUER` | App Store Connect → Users → Keys |
| 钥匙串 profile | `NOTARY_PROFILE` | 先执行 `xcrun notarytool store-credentials "AC_NOTARY" --apple-id ... --team-id ... --password ...` |
| Apple ID | `APPLE_ID`、`APPLE_APP_PASSWORD`、`APPLE_TEAM_ID` | 应用专用密码，不是账号密码 |

流程：`notarytool submit --wait` → `stapler staple` → `spctl -a -vvv -t exec` 校验。

### 3.4 常见坑

- 公证提交 `.app` 前要 `ditto -c -k --keepParent` 成 zip；脚本已处理。
- 先构建 dmg 再签名会导致 dmg 内仍是未签名副本；`build-macos.sh` 在签名后会用 `hdiutil` 重新打包 dmg。
- `allow-jit` 缺失时 WKWebView 启动即崩；`disable-library-validation` 缺失时 sidecar 加载失败。
- 公证失败看 `xcrun notarytool log <submission-id>`，多数是某个嵌套二进制没签名或没时间戳。

## 4. CI 接入建议（可直接照抄）

```yaml
# Windows
- run: npm ci
- run: npm run tauri build -- --bundles nsis
- run: powershell -File scripts/sign/build-windows.ps1 -Sign -RequireSign
  env:
    WINDOWS_CERT_PFX: ${{ secrets.WINDOWS_CERT_PFX_BASE64 }}   # 先解码为文件
    WINDOWS_CERT_PASSWORD: ${{ secrets.WINDOWS_CERT_PASSWORD }}

# macOS
- run: npm ci
- run: ./scripts/sign/build-macos.sh --notarize
  env:
    APPLE_SIGNING_IDENTITY: ${{ secrets.APPLE_SIGNING_IDENTITY }}
    APPLE_API_KEY: ${{ secrets.APPLE_API_KEY_PATH }}
    APPLE_API_KEY_ID: ${{ secrets.APPLE_API_KEY_ID }}
    APPLE_API_ISSUER: ${{ secrets.APPLE_API_ISSUER }}
```

> PFX 在 CI 上建议 base64 存储后在步骤里解码；不要把证书或密码提交进仓库。
