# 交接说明（Renomio → 新开发者）

> 目的：把「一个人脑子里的项目记忆」变成「另一个人能独立接手、发版、排查」的可执行资料。
> 适用版本：`1.1.0-alpha7`（2026-11-11 发布）。本文件只写结论与入口，细节由仓库内既有文档承担。

## 0. 先理解：记忆分三层，只有第一层能放仓库

| 层 | 内容 | 交接方式 |
| --- | --- | --- |
| 仓库事实 | 代码、提交历史、`docs/`、CI、`CONTRIBUTING.md`、本文件、`AGENTS.md` | 已在仓库里，clone 即可 |
| 会话记忆 | 与 AI 助手/前开发者对话里形成但没落盘的决定、踩过的坑 | 必须**主动固化成文档**（本文件第 7–10 节 + `AGENTS.md`），否则换人即丢失 |
| 外部资产 | GitHub 账号与权限、发布权、签名私钥、CI Secrets、域名/邮箱 | 走第 10 节的权限与密钥清单，不写在代码里 |

**操作顺序**：① 先读本文件 → ② `git clone` 后按第 3 节跑通一次构建与测试 → ③ 让新开发者的 AI 助手加载根目录 `AGENTS.md` → ④ 按第 10 节完成账号/密钥交接 → ⑤ 新开发者独立打一个补丁版本（例如 alpha8）作为验收。

## 1. 项目是什么

Renomio 是 Windows 桌面的批量重命名工具（原名 Rename Studio / `ffrn`）：拖入文件 → 规则链命名 → 即时预览 → 落盘执行 → 可撤销；另含照片/音乐/文档元数据、快照、文本编码转换、文件属性等操作。

- 源码：<https://github.com/yunyu697/renomio>（公开）
- 发布：同一仓库的 Releases（旧的 `renomio-releases` 已归档，只留历史下载）
- 版本：稳定版 `v1.0.0`；当前预发布 `v1.1.0-alpha7`；`VERSION` 文件与最新发布保持一致
- 许可证：见 `LICENSE`；第三方组件见 `THIRD-PARTY-NOTICES.md`

## 2. 代码地图

```
app/                        前端 + Tauri 壳（一个 npm workspace 根）
  src/                      React 19 + TypeScript
    store.ts                唯一的 zustand store（状态与所有跨组件动作）
    lib/bridge.ts           唯一的 Tauri invoke 出口（浏览器里自动落到 mock）
    lib/types.ts            前后端 DTO
    lib/plans.ts            方案库/最近记录（localStorage）
    components/             UI（Nav、RulesPanel、ListView、OpsBodies、PlansDialog…）
    styles/                 app.css / shell.css（设计变量、九类视图样式）
  src-tauri/                Rust 壳
    src/lib.rs              命令注册（rename/scan/ops/text/meta/attrs/icons…）
    src/icons.rs            SHGetFileInfoW → PNG（系统文件类型图标）
    src/migrate.rs          旧版配置/撤销历史迁移
    src/update.rs           更新检查
    renomio-core/           纯 Rust 核心，可独立 cargo test
      rename.rs scan.rs     改名与扫描
      ops.rs                属性/时间/哈希等真实文件操作
      textedit.rs           文本编码探测与转换（含批量）
      metaedit/             图片/音频/文档元数据读写
      journal.rs snapshot.rs 撤销与快照
  scripts/                  version.mjs、check-version.mjs、gen-test-corpus.mjs、check-bundle.ps1、gen-icons.mjs、verify/cdp.mjs
  e2e/run.mjs               无头浏览器 E2E（mock 后端，断言 + report.md/json）
  packages/foundation/      共享基础层
docs/                       见第 12 节索引
design/                     设计稿/视觉参考
.screenshots/               视觉回归截图
```

要点：
- 前端所有后端调用都经 `app/src/lib/bridge.ts`；新增命令要同时改 `lib.rs`（注册）、`types.ts`、`bridge.ts`。
- `renomio-core` 不依赖 Tauri，文件类逻辑与测试优先放这里（`cargo test` 可直接跑）。
- 规则链的语义与验收口径见 `docs/规则语义确认清单.md`，改规则前必读。

## 3. 环境搭建（Windows 10/11 x64）

1. **Node 22**（`node -v` ≥ 22），**Rust stable + MSVC 工具链**（`rustup default stable-x86_64-pc-windows-msvc`）。
2. **Visual Studio Build Tools**（C++ 桌面开发负载）与 **WebView2 Runtime**（Win11 自带）。
3. 安装依赖：`cd app && npm ci`。
4. 冒烟：`npm run build`、`npm run test:core`、`npm run test:e2e`。
5. 打包：`npm run tauri build`（NSIS 与 WiX 工具由 Tauri 首次构建时自动下载，需要网络）。
6. CI 只在 Linux 跑前端与 Rust 测试，**不构建安装包**；安装包一律本地 Windows 构建。

## 4. 日常命令（全部在 `app/` 下）

| 目的 | 命令 |
| --- | --- |
| 类型检查 + 生产构建 | `npm run build` |
| Rust 核心测试 | `npm run test:core` |
| 无头 E2E（244 条） | `npm run test:e2e` |
| 拖放状态机自测（21 条） | `npm run test:drop` |
| 输入历史自测（26 条） | `npm run test:history` |
| 对比度检查 | `npm run test:contrast` |
| 打包产物断言（11 离线 + 14 产物） | `npm run test:bundle` |

| 构建安装包 | `npm run tauri build` |

失败一律先读日志（`build.log` / `test.log` / `e2e-run.log`），不要靠肉眼点界面判断。

## 5. 运行数据落在哪里

- 配置、撤销历史、迁移备份、日志：`%APPDATA%\app.renomio.desktop`（与安装范围无关）。
- 撤销日志追加写 `logs/undo.log`。
- 前端本地存储（WebView2 用户数据目录）：`rename-studio.session`（会话）、`renomio.saved-plans`（方案库）、`renomio.recent-items`（最近 10 条）。
- 卸载不会删数据目录；交接/排障时注意区分「程序问题」与「本地数据问题」。

## 6. 硬性约定

见 `CONTRIBUTING.md`，三条最容易违反的：
1. 构建/测试/截图一律后台执行，日志落盘；不要在会话里弹 GUI、不要抢焦点。
2. 文件操作验收必须脚本化（临时目录 + 断言），不靠人工点界面。
3. 交付说明如实区分「已验证 / 未验证 / 未实现」，不伪造通过。

## 7. 版本与发布流程（当前实际做法）

1. 改 `VERSION`（单一来源），例如 `1.1.0-alpha8`。
2. `cd app && npm run version:sync`（同步根 `VERSION`、`app/package.json`、`packages/foundation/package.json`、`tauri.conf.json`、两个 `Cargo.toml`；`version:check` 在 CI 中强制一致）。
3. `npm run tauri build` → 产物在 `app/src-tauri/target/release/bundle/{nsis,msi}/Renomio_<版本>_x64*`。
4. `npm run test:bundle`（无产物时只跑 11 条离线断言）。
5. 计算两包 SHA-256，生成 `SHA256SUMS`（两条，`hash  filename` 两空格）。
6. 更新根 `README.md` 与 `app/README.md` 的产物表（文件名、字节数、SHA-256）。
7. 提交（功能提交与 `chore(release)` 分开）→ `git tag -a v1.1.0-alpha8` → 推 `main` 与 tag。
8. `gh release create v1.1.0-alpha8 -R yunyu697/renomio --prerelease --notes-file <说明> 两个安装包 SHA256SUMS`。

**必须知道的现状**：
- 构建环境没有 `TAURI_SIGNING_PRIVATE_KEY`，`tauri build` 在产出两个包后以「有公钥无私钥」**退出码 1**（包本身是完整的）；因此 alpha6/alpha7 都**没有 `.sig`**。
- 自动更新清单在 `updates` 那一版 release 的 `latest.json`，目前仍指向 `1.1.0-alpha5`。没有私钥就不要改它；新开发者若需要自动更新，必须先取得或重新生成 minisign 密钥（公钥在 `tauri.conf.json` 的 `plugins.updater.pubkey`），换密钥意味着老用户无法平滑更新。
- 两个安装包都**未做代码签名**，首次运行会触发 SmartScreen。签名/公证的现状与脚本入口见 `docs/签名与打包流程.md`。

## 8. 当前完成度与已知问题

- 1.1.0 的收口清单（F2 方案库、F3 SYSTEM/ARCHIVE、F4 文本编码批量、U3 自动列宽 + 系统图标等）与逐项验收证据：`docs/1.1.0-收口清单.md`。
- 功能矩阵与和竞品的差距：`docs/FEATURE-GAP.md`。
- 已实现但未在真机验证的项目（真实 Explorer 拖放、提权拖放、安装向导/UAC、macOS/Linux 构建、三套译文本母语审校等）：根 `README.md`「已知限制」。
- 已知测试噪声：`renomio-core` 的 `rename::tests::directory_junction_is_renamed_as_a_link` 在部分环境因权限/联接点创建失败而失败，属环境相关，不是本轮改动引入。
- 平台：当前只发布 Windows x64；macOS/Linux 配置在代码里但未构建、未验证。

## 9. 建议的下一步（按价值排序）

1. 决定更新签名密钥的归属（继续用现有公钥 / 重新生成），补齐 `.sig` 并恢复 `latest.json` 发布链路。
2. 代码签名证书（OV/EV 或 Azure Trusted Signing），消除 SmartScreen 警告。
3. 真机验收清单化：安装/卸载、Explorer 拖放、提权拖放、真实相机样张 EXIF。
4. 若要做 macOS/Linux：先跑通 CI 构建，再补签名/公证流程。
5. 译文母语审校（繁中/日/西）。

## 11. AI 助手怎么拿到「记忆」

- 仓库根目录的 `AGENTS.md` 已写好项目事实、命令、约束与常见坑；Trae / Cursor / Claude Code 等支持该约定的工具会自动读取。
- 使用其他工具时，把 `AGENTS.md` + 本文件作为首轮上下文贴入。
- 不要在对话里依赖「上次那个会话说过」，任何影响后续开发的决定都要落到 `docs/` 或提交信息里。
