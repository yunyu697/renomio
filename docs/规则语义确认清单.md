# 规则语义确认清单

> 目的：把当前实现中「看起来有多种合理答案」的 10 条语义摊开，逐条给出当前行为、建议默认值、改动影响与理由。
> **确认结果（2026-11-04）**：8 条保持现状；#7 落地「包含隐藏文件」开关（默认开启）；#9 在 UI 与文档明确「执行顺序 = 扫描顺序」。落地明细见文末「确认结果与落地状态」。

- 代码基线：`app/src/lib/rules.ts`、`preview.ts`、`validate.ts`、`moveRules.ts`；`app/src-tauri/ffrn-core/src/{scan,rename,platform}.rs`
- 影响判定口径：
  - **规则**：用户已配置的规则链在下次预览时是否产出不同名字。
  - **方案 JSON**：导入/导出文件是否还能被当前版本接受（schema / 字段 / 校验）。
  - **结果**：同一方案在同一目录重复执行是否得到不同文件名。

## 总表

| # | 语义点 | 当前实现 | 建议默认 | 改成建议值的影响 | 为什么这样建议 |
| --- | --- | --- | --- | --- | --- |
| 1 | 编号基准（从 0 还是 1、按什么顺序） | `NumberRule.start` 默认 **1**，`step` 默认 1；计数键为 `规则id::父目录`（`perFolder` 时）或 `规则id::''`；按 **扫描后的列表顺序**（完整路径小写升序）依次取号；列头点击排序只改显示，不改编号；未勾选且 `onlyChecked=false` 的条目也占号 | 保持 **从 1 开始**；明确「按扫描顺序（路径升序）」；保留 `start=0` 能力但不改默认；`onlyChecked` 默认 `false` | 规则：改默认值会立刻改变已有规则的编号输出；方案 JSON：字段已显式存 `start`，schema 不变，旧方案仍按 1 起；结果：跨版本可能不同 | 与用户直觉和主流更名工具一致；扫描顺序稳定、可复现，撤销与批次记录才能对应 |
| 2 | `<#>` 是否仅占位 | 编号表达式**必须**包含 `<#>`，否则该规则被 `ruleError` 跳过；`split('<#>').join(编号)` 替换**所有**出现；编号按 `digits`（默认 3）+ `padChar`（默认 `0`）格式化 | 保持：`<#>` **仅作编号占位**，全量替换；不引入转义语法；文档写明「需要字面 `#` 时不要写成 `<#>`」 | 规则：无变化；方案 JSON：无变化；结果：无变化。若未来新增转义（如 `<<#>>`），旧的含 `<<#>>` 方案输出会改变 | 语义越少越可预期；转义一旦引入就难以回退 |
| 3 | 正则方言（JS `RegExp` vs Rust `regex` crate） | 规则求值**全部在 TS**：`new RegExp(pattern)`，`caseSensitive=false` 时加 `i`；Rust 核心**没有 regex 依赖**，只校验前端算好的目标名与路径；方案 JSON 存 pattern 原文 | 保持 **ECMAScript `RegExp`** 为唯一方言；后端永不解释 pattern；若未来要迁移到 Rust，必须先做语法兼容层与降级提示 | 规则：无变化；方案 JSON：无变化；结果：无变化。若改为 `regex` crate，含 lookaround / 反向引用 / JS 特有语法的方案会直接失效 | 预览与执行同源，才能保证「看到的就是写下去的」；两套引擎必然产生差异 |
| 4 | 随机大小写种子与可复现性 | 种子 = **FNV-1a(`规则id|当前stem`)**，PRNG 为 `mulberry32`；同一文件名 + 同一规则 id 输出稳定；前序规则改变 stem、或删除重建规则（id 变化）都会改变结果；无用户可见 seed | 保持「按当前 stem + 规则 id 稳定」；在 UI 文案写明随机结果随规则 id 变化；未来可加可选 `seed` 字段，缺省维持旧行为 | 规则：无变化；方案 JSON：新增可选字段不破坏旧文件；结果：若改为全局固定种子，已有方案输出会变 | 稳定性保证预览重算一致，又允许用户通过重建规则获得新的随机分布 |
| 5 | 长路径阈值（260 是否仍是上限） | 组件上限 **255**（Linux 按字节、Windows 按字符）；全路径：警告阈值 Win **240** / macOS 900 / Linux 3800，硬上限 Win **32767** / macOS 1024 / Linux 4096；Windows 绝对路径统一加 `\\?\` 前缀 | 保持现值；在 UI/文档注明 **260 不再是硬限制**（已被 `\\?\` 绕过），240 是「提前亮黄灯」的提示阈值 | 规则/方案 JSON：无影响；若把提示阈值改到 260，用户会更晚看到警告，长临时名（`.ffrn-<batch>-<i>.tmp`）更容易顶到上限 | 240 给临时名与后缀留出余量；32767 才是 NTFS 的真实边界 |
| 6 | 扩展名大小写归一 | `splitName` 以**最后一个 `.`** 切分，扩展名保留原始大小写；只有「扩展名规则」的 `case` 模式才 upper/lower；冲突/去重比较走 `normalizePath`（大小写不敏感平台转小写）；扫描排序按路径小写 | 扩展名的**匹配与分组**默认大小写不敏感（`.JPG` 与 `.jpg` 视为同一类）；**输出保留**规则/用户给出的写法，主体大小写不动 | 规则：归类分组的合并会改变目录结果（行为变化），但现有方案 JSON 字段不变；若改 `splitName` 的切分规则，预览名会变 | 扩展名在三大平台实际都不区分大小写；但擅自改文件名大小写属于意外修改 |
| 7 | 隐藏文件与前导点 | 扫描**不排除**隐藏/点文件，也没有「包含隐藏文件」开关；`.gitignore` 因首个 `.` 在位置 0，被视为**无扩展名**；`a.`（尾点）被切成 stem `a` + 空扩展名，拼回后尾点丢失；Windows 隐藏属性只在属性面板可改 | 默认**仍包含**隐藏文件，但增加「包含隐藏文件」开关（默认开）；点文件保留原名、不把前导点当扩展名；尾点**原样保留**，由校验提示「结尾是点」而不是静默删除 | 规则：新增开关不影响旧配置；若默认改为排除隐藏文件，已扫描列表与批量结果会变；尾点保留会改变含尾点文件的预览名 | 静默修改 `.env`、`.git` 一类文件风险最高；尾点被吞掉属于看不见的数据变更 |
| 8 | Unicode 归一化（NFC/NFD，macOS） | 实际文件名与规则输出**不做任何归一化**；`normalizePath` 仅在**比较**时 `.normalize('NFC')` + 大小写折叠；macOS 可能返回 NFD 文件名，用户输入 NFC 时预览可能显示「未变更」，但字节并不相同 | 保持「不改字节」；比较统一 NFC（现状）；在 macOS 上把「仅归一化差异」单独标注为「等价名（未变更）」，写入必须显式确认 | 规则：无变化；方案 JSON：无变化；若对输出强制 NFC，macOS 上 NFD 文件会被真实改名，属于字节级修改 | 归一化是不可逆的字节变更，跨平台复制/同步时最容易引发重复文件，默认不应静默做 |
| 9 | 排序稳定性 | 扫描用 Rust `sort_by`（**稳定排序**），键 = 小写完整路径，再用原路径作次级键；预览、编号、批次执行都沿用这份顺序；列头排序只影响显示 | 明确「**执行与编号顺序 = 扫描顺序（路径升序、稳定）**」；列头排序不改执行顺序；若后续支持手动排序，单独存 `manualOrder` 字段 | 规则：无变化；方案 JSON：无变化；若改为按当前显示顺序执行，用户点一次列头就会改变编号与批次顺序 | 可撤销、可复现、可对比都依赖同一份稳定顺序 |
| 10 | 冲突后缀 `(1)` 的递增与语言影响 | `suffix` 策略从 attempt=1 试到 **999**：文件为 `stem (n).ext`，无扩展名为 `stem (n)`，目录为 `name (n)`；使用**半角空格 + 半角括号 + ASCII 数字**，不受系统区域设置影响；批次内目标先去重 | 保持半角 + ASCII、从 **1** 递增、上限 999 后报错；在文档写明「与系统语言/区域无关」 | 规则：无变化；方案 JSON：策略存在应用选项/设置而非方案字段，无兼容问题；若改全角/本地化数字或从 0 起，会改变用户既有文件命名与自动化脚本的匹配 | 跨平台可预测、便于正则与脚本处理；本地化数字会让同一方案在不同机器产出不同名字 |

## 需要特别注意的三处交叉影响

1. **#1 与 #9 强耦合**：编号顺序来自扫描顺序；如果之后加「手动排序」而不把顺序持久化进批次，撤销时行号会对不上。
2. **#3 与方案导入导出**：现在方案 JSON 只存 pattern 文本，不做正则语法校验。若未来换引擎，**必须**在导入阶段逐条编译并给出「哪条规则在哪个方言下不可用」，否则会出现导入成功、预览失败。
3. **#6/#7/#8 都涉及「不改字节」原则**：扩展名大小写、尾点、Unicode 归一化，建议统一策略——**默认只读地比较与提示，不静默改写文件名**。

## 建议的处理顺序（历史记录，#7/#1/#9 已落地）

| 优先级 | 事项 | 预估改动面 |
| --- | --- | --- |
| 高 | #3 正则方言文档化 + 导入时编译校验 | 仅前端校验与提示，无行为变化 |
| 高 | #7 增加「包含隐藏文件」开关（默认开，保持现状） | 扫描选项 + 设置项 + 测试 |
| 中 | #1/#9 把「扫描顺序 = 执行顺序」写进 README 与预览提示 | 文档 + 提示文案 |
| 中 | #10 上限 999 的失败提示与文档 | 错误文案 |
| 低 | #4 可选 `seed` 字段、#8 macOS 等价名标注 | schema 迁移 + macOS 专项测试 |
